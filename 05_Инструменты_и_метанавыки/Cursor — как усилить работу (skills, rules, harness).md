## Зачем этот документ

Cursor — не «чат с GPT», а **coding harness**: агент с tools, контекстом, правилами и навыками. Чем лучше настроен harness, тем меньше повторяешь одно и то же в каждом чате.

Цель: **понять skills и соседние механизмы** → вынести повторяющиеся практики в файлы → получать стабильный результат в Obsidian, коде и рабочих задачах.

---

## Карта усилителей (от простого к сложному)

| Уровень | Что это | Где лежит | Когда использовать |
|---------|---------|-----------|-------------------|
| **User Rules** | Глобальные предпочтения (язык, стиль, git) | Cursor Settings → Rules | Всегда: «пиши по-русски», «не коммить без запроса» |
| **Project Rules** | Правила под репозиторий / vault | `.cursor/rules/*.mdc` | Конвенции vault, шаблоны заметок, формат эпиков |
| **Skills** | Пошаговые инструкции под задачу | `~/.cursor/skills/` или `.cursor/skills/` | Повторяемые workflow: PR, конкурентный анализ, оформление эпика |
| **@-mentions** | Явный контекст в чате | `@файл`, `@папка`, `@code` | Когда нужен конкретный документ прямо сейчас |
| **MCP** | Внешние инструменты (браузер, GitHub, …) | Настройки MCP | Когда агенту нужен доступ вне workspace |
| **Hooks** | Скрипты до/после действий агента | `.cursor/hooks.json` | Аудит, блокировка команд, автодополнение контекста |
| **Automations** | Запуск агента по триггеру | Cursor Automations | Регулярные задачи: triage PR, синк бэклога |

**Правило большого пальца:** если объясняешь одно и то же **в третий раз** — пора в **skill** или **rule**.

## Skills — что это и чем отличается от rules

**Skill** — папка с `SKILL.md`: markdown-инструкция, которую агент подхватывает, когда задача подходит под `description` в frontmatter.

```
my-skill/
├── SKILL.md          # обязательно
├── reference.md      # опционально — детали
├── examples.md       # опционально — примеры
└── scripts/          # опционально — скрипты
```

### Где хранить

| Тип | Путь | Область |
|-----|------|---------|
| Личный | `~/.cursor/skills/skill-name/` | Все проекты |
| Проектный | `.cursor/skills/skill-name/` | Только этот репозиторий |

**Не трогать:** `~/.cursor/skills-cursor/` — встроенные skills Cursor (create-skill, create-rule, automate, …).

### Минимальный SKILL.md

```markdown
---
name: obsidian-epic
description: Создать или обновить эпик в Obsidian vault по шаблону ДорХаб/Бизнес OS
---

# Эпик в Obsidian

1. Спросить название, дату, связанные люди.
2. Искать шаблон в `Zettel/.../Эпики/`.
3. ...
```

### Skills vs Rules

| | **Rules** | **Skills** |
|---|-----------|------------|
| Назначение | Ограничения и стиль | Процедура «как сделать X» |
| Срабатывание | always / по glob | По смыслу задачи (description) |
| Объём | Короткие | Могут быть длинными, со скриптами |
| Пример | «Не создавай .md без запроса» | «Как оформить конкурентный анализ» |

**Миграция:** старые slash-команды (`.cursor/commands/`) и «умные» rules без glob → можно перевести в skills (см. встроенный skill `migrate-to-skills`).

## Что уже имеет смысл для твоего vault

### 1. User Rules (уже частично есть)

Зафиксировать то, что повторяется в каждом чате:

- русский язык в ответах;
- не коммитить без явного запроса;
- минимальный scope правок;
- Obsidian: не плодить лишние README.

### 2. Project Rules для My_Osbidian

Примеры `.cursor/rules/`:

- `obsidian-notes.mdc` — frontmatter, wikilinks `[[...]]`, даты в заголовках;
- `backlog-format.mdc` — формат чекбоксов в `БЭКЛОГ ВСЕГО`;
- `dorhub-epics.mdc` — структура эпиков ДорХаб.

### 3. Skills под повторяющиеся задачи

| Skill (идея) | Триггер |
|--------------|---------|
| `competitive-intel` | «конкурентный анализ», «разведка» → шаблон из Business OS |
| `backlog-item` | «добавь в бэклог» → правильная секция + ссылка |
| `health-note` | новая мед-заметка → Health OS + дата |
| `daily-journal` | «запиши в дневник» → `Zettel/Дневники/` |
| `habr-to-cheatsheet` | статья → шпаргалка в `Notes_Tutorials_CheetSheet` |

Создавать по одному, когда workflow уже отработан руками 2–3 раза.

### 4. @-контекст в чате

Перед задачей подключать:

- `@БЭКЛОГ ВСЕГО (BACKLOG ALL).md` — при планировании;
- `@Шаблон — конкурентный анализ` — при разведке;
- `@SYSTEM.md` — при вопросах о структуре vault.

### 5. Режимы агента

- **Agent** — правки файлов, терминал, многошаговые задачи.
- **Ask** — только объяснить / найти, без правок.
- **Plan** — большой рефакторинг или неясная постановка.

Для vault чаще всего **Agent**; для «объясни эпик» — **Ask**.

## Как писать запросы в Cursor (коротко)

1. **Цель** — что должно получиться («добавь в бэклог + шпаргалку»).
2. **Контекст** — ссылки, даты, ограничения («без коммита», «только раздел Развитие»).
3. **@файлы** — шаблоны и эталоны.
4. **Один фокус на чат** — эпик / бэклог / код, не всё сразу.
5. **Итерация** — «сократи», «перенеси в другую секцию», «добавь в MOC».

См. также [[ChatGpt]] — база промптов (цель, задача, контекст, роль, лимиты).
